# Choosing and preparing the source data

This project started by looking for a Malaysian dataset suitable for a visualisation exercise. SWTS was selected because its CSVs are publicly available and its report provides the research context. That allowed the work to focus on presenting existing evidence rather than developing a new policy analysis.

## Narrowing the scope

The report's discussion of TVET led to two topics: school pathways by ethnicity and salary offers by qualification. Only the two modules needed for those visuals are retained:

| File | Role in the notebook |
| --- | --- |
| `SWTS_InSchool.csv` | School-pathway distribution within each ethnic group |
| `SWTS_Employer.csv` | Maximum salary offers for the selected `A1 = 3` employer group |

The original CSVs are read without modification. Calculations take place in the notebook; no derived CSVs are created.

## Bringing the sources together

The CSVs contain records and category codes, but interpreting them requires supporting sources. KRI's [SWTS dataset page](https://www.krinstitute.org/publications/the-school-to-work-transition-survey-swts-of-young-malaysian) supplies column definitions and links to the survey instruments. The report supplies the policy context and published comparisons.

The website metadata was extracted on **2 October 2026** and stored alongside a local file inventory. Comparing these sources exposed coding differences, particularly for employer type. The notebook therefore describes the selected CSV group and records the uncertainty rather than assuming that every questionnaire label transfers to the export.

Use the supporting documents in this order:

1. [Provenance](PROVENANCE.md): where the files came from, their dimensions and survey context.
2. [Metadata and mappings](metadata/README.md): how the fields and category codes are interpreted for each visual.
3. [Report references](report/README.md): the published findings that guided the choice of visuals.

## Recording the report's claims

[section_evidence.json](report/section_evidence.json) records the report claims that guided the two visuals in a structured format the notebook can read. Each entry includes the claim, its printed page, any reported value and unit, and its relationship to the visual. Approximate salary differences are marked as approximate, and the file also records the report citation, source links and PDF page references.

The entries were compiled from the report rather than generated by a new analysis. The notebook displays them as an evidence inventory, then calculates its chart data separately from the original CSVs. This keeps the published findings and the notebook's unweighted sample results clearly identified.

## Moving to the notebook

The report uses survey weights, but no weight field is available in either released CSV. The notebook therefore calculates unweighted sample summaries and displays response counts, rather than claiming to reproduce the published population estimates.

Continue with the [notebook guide](../notebooks/README.md) to see how these inputs become the two visuals. The planned app will later use SQLite to serve the selected data; that step is not implemented yet.
